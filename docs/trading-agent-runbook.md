# Recurring $20 trading trial

Run against the local Thesis Ledger project with the official Robinhood Trading MCP and Thesis Ledger trader MCP. This trial uses the accessible MCP account, selected for this trial. The user authorized stocks and ETFs, up to $20 total gross purchases, dollar-based market orders during regular hours, with every order manually approved in Robinhood. Keep these financial records private.

1. Read the private dashboard with `get_private_trading_dashboard`. Resolve the broker account with `get_accounts` and use only the accessible MCP account. Follow the current tool descriptions. Check the NYSE calendar and America/New_York time. Outside an open regular session, reconcile account state and outcomes and save them, then end without proposing a new regular-hours order request.
2. Fetch `get_portfolio`, `get_equity_positions`, `get_equity_orders` (all equities since 2026-11-16, including user and other-agent orders), `get_trade_approvals`, `get_trade_approval_setting`, and `get_realized_pnl` for equity/all. Follow every pagination cursor and combine pages. For held stocks fetch `get_equity_quotes` so open P&L has actual prices. Pass the data fields of those responses into `sync_robinhood_dashboard`. Never substitute older values or invented zeros when a broker call fails.
3. Reconcile recorded trade events first. A pending approval may be approved, declined or expired. Retrieve the current approval by ID. An approved order still needs order-status reconciliation. Match order.ref_id to the saved approval ID when Robinhood changes the ref_id on approval. Record the observed lifecycle with `record_robinhood_trade_event`, preserving proposal ID, side, stock and amount. Never report pending or approved as filled. If submission failed ambiguously, reconcile its existing ref_id and approval/order IDs before retrying. Reuse the same idempotency key.
4. If an existing `review_requested` proposal needs broker review, handle that proposal before researching another purchase. If an approval is pending, retain the reservation, sync and finish. Do not send duplicate approval requests. If there are open unfilled orders, reconcile those before another overlapping proposal.
5. Choose 2–3 candidate stocks/ETFs using the latest market brief and headlines, and include every held stock for exit review. Honor any queued review list in the dashboard, within five symbols including holdings. Start with SPY, AMZN and GOOGL when no held stock or new market evidence suggests a more relevant candidate. Fetch `get_equity_fundamentals` for those symbols and pass its data field as broker_fundamentals to `run_private_trading_cycle`. Today's valuation fields are preserved as Robinhood evidence in each report. It runs the specialist analysts, debate, manager and risk review, compares eligible reports, reviews past outcomes, saves reasoning and reserves at most one proposal. The amount is capped by remaining trial funding and current unleveraged buying power. If it abstains, record that outcome and finish. Never force a buy to use the allocation.
6. For a returned proposal, recheck `get_trade_approval_setting` immediately before any order request and require true. Check current `get_equity_tradability`, quote, cash and, for sales, shares_available_for_sells. Use exactly the proposed symbol, side and dollars. Do not short sell or borrow. Call `review_equity_order` with type=market, time_in_force=gfd, market_hours=regular_hours and the dollar amount. If customer_approval_required is not true, stop and document the block. If order_checks is nonempty, follow the broker tool's instructions and obtain any required confirmation before proceeding.
7. When the review explicitly requires customer approval and has no broker alert, call `place_equity_order` with the exact reviewed parameters and ref_id=proposal.id. This must create a pending approval in Robinhood. Record its approval ID and `awaiting_approval`. On uncertain transport failure, record `submission_unknown` and reconcile before retrying. The user approves or declines in Robinhood. Do not approve on their behalf.
8. Sync broker state after a meaningful change. All suggestions, abstentions, analyst reports, sources, manager reasoning, risk findings, approval states, fills and later outcomes belong in the private Trading timeline. Alert the user for a new approval request, fill, material risk or action needed. Subsequent reviews use the recorded outcomes as experience. Once the $20 purchase funding is spent or reserved, continue holding/sell reviews and outcome tracking. A sale does not authorize another purchase cycle or increase the funding limit.

If trader MCP tools are absent in this session, run the same functions from `ledger.trader_mcp` and `ledger.trading_dashboard` using the project's `.venv/bin/python` and `load_config()`. The local .env contains the private dashboard token. Never print it, commit it, put it in URLs or send it to another destination. Use `publish_record` for private record writes and the authenticated dashboard for reads. A queued review is marked complete by `private_cycle` after its matching candidates are reviewed.
